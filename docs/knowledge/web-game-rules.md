個人開発の共有ナレッジへ持っていくための短縮版。
**このファイルだけで実用に足りる**ように、プロジェクト固有の話は全部落としてある。

- 「なぜそうなのか」「実測値」「そこに至った経緯」が要るときだけ、
  詳細版 [ITCH-MOBILE.md](./ITCH-MOBILE.md) を見る（約61KB／2.5万トークン相当あるので常時読み込みは非推奨）。
- ここは**約16KB／6〜7千トークン相当**。詳細版の約1/4。
- さらに軽くしたいときは、**§0・§7・§8 だけ（約2KB）** を CLAUDE.md に貼り、
  §1〜§6 は「必要になったら開く参照」にすればよい。

出典の区別：★ = itch.io 公式ドキュメント記載、● = 自分たちが実機・計測で確認。

## 0. 最優先の3つ

1. **入力リスナーを `window` だけに付けない。** iframe 埋め込み（itch.io 等）では
   `window` に一切イベントが届かないことがある。●
2. **「直したのに直らない」が2回続いたら、修正内容を疑う前に
   “本当に新しいコードが動いているか” を確認する。** 画面に BUILD ID を出す。●
3. **スマホにはコンソールが無い。** 推測で直す前に、
   **端末の画面に数字を出す手段**を先に作る。それが無い間の修正は全部あてずっぽう。●

## 1. itch.io に HTML5 ゲームを出すとき

- ★ **モバイルでは必ず「Run game」ボタンが出て、必ず全画面で起動する。**
  プロジェクト設定の「Automatically start on page load」は**モバイルでは無視される**。
  → **このボタンの有無で「デプロイが反映されたか」を判断してはいけない。**
- ★ アカウント設定の「Require a click to run HTML5 game embeds」は
  **プロジェクト設定を上書きする**（PC のみ）。自分のアカウントで検証していると、
  設定を直しても自分の目には変化が無い。
- ★ 「Mobile friendly」を外しても**ゲームは動く**。警告が出るだけ。
  対応済みなら入れておく（警告が消えて印象が良い）。
- ● **butler の channel push は「1つの upload に build を積む」方式なので、
  配信される `index.html` の URL が変わらない。**
  → 端末と CDN に古い `index.html` が居座り、そこから参照される
  ハッシュ付き JS も古いまま固定される。**これが「直したのに直らない」の主犯。**
  → §5 のキャッシュ対策を最初から入れる。

## 2. 入力（ここが一番ハマる）

### 2-1. リスナーは多重登録する

```
canvas → コンテナ → body → documentElement → document → window
```
の順に**全部**登録し、**最初に受け取った系統だけが処理**する（重複排除）。

```ts
const handled = (e: Event): boolean => {
  const ev = e as Event & { __seen?: boolean };
  if (ev.__seen) return true;
  ev.__seen = true;
  return false;
};
// 各ハンドラの先頭で: if (handled(e)) return;
```

- `capture: true` で登録する（途中で `stopPropagation` されても先に届く）。
- どの系統で届いたかを**デバッグ表示に出す**（後で効く）。

### 2-2. タッチは Touch Events を主系統に

- iOS のクロスオリジン iframe では、WebKit が `pointerdown` の直後に
  `pointercancel` を投げてくることがある。すると
  「タップは効くのに、ドラッグもホールドも効かない」という紛らわしい壊れ方をする。●
- **Touch Events は `preventDefault` していれば `touchmove` / `touchend` が確実に届く。**
- Pointer Events はマウス用に残す。
  タッチについては「一度でも `touchstart` を受けたら Touch 側を正」にすれば二重入力しない。

### 2-3. 解放経路は多重化する

`pointerup` / `pointercancel` / `lostpointercapture` / `touchend` / `touchcancel` /
`blur` / `pagehide` / `visibilitychange` の**全部**で解放し、さらに
**一定時間イベントが来ない指を無効化するウォッチドッグ**を置く。

**絶対にやってはいけない設計：**

```ts
// ✗ 最初の指のIDを保持し、touchend が来るまで新しい入力を全部弾く
if (this.activeTouchId !== null) return;
```

解放イベントを1回取りこぼすだけで**入力が永久に死ぬ**。
指は ID をキーにした Map で管理し、**古い状態が新しい入力をブロックする経路を作らない**。

### 2-4. 最後の砦に本物の DOM `<button>` を置く

タイトル画面に透明な `<button>` を重ねておく。ネイティブの `click` は
タッチもポインタも全滅する環境でも届くことがある。●

- **既定で表示**にする（描画ループが死んでいても操作手段が残る）。
- **その要素の上では `touchstart` を `preventDefault` しない。**
  iOS は既定動作を止めると `click` を発火しなくなり、最後の砦が無効化される。
- 通常経路が生きているときは二重入力になるので、直前に `pointerdown` が
  来ていたら無視する。

### 2-5. 単発タップを取りこぼさない

押した直後に解放イベントが来る環境があるので、
発射条件には**押しっぱなし判定だけでなく「押した瞬間」フラグも含める**。

### 2-6. 座標変換のフォールバック

`getBoundingClientRect()` が 0 を返すと、全タッチが座標 (0,0) 扱いになり
「画面左半分」に吸い込まれる等の不可解な壊れ方をする。
0 のときはビューポート基準に切り替える。

## 3. 起動とループの堅牢性

### 3-1. `requestAnimationFrame` の再登録は必ず `finally`

```ts
function loop(t: number) {
  try { update(t); draw(); }
  catch (e) { showErrorOverlay(String(e)); }
  finally { requestAnimationFrame(loop); }   // ← ここ
}
```

再登録が `try` の中にあると、**例外1回でループが永久停止**する。
画面には最後のフレームが残ったままなので、**「入力が効かない」としか見えない。**
原因調査が極端に難しくなる、最悪の壊れ方。●

### 3-2. フレーム毎の後始末も `finally`

「押した瞬間」フラグのクリアを早期 `return` で飛ばすと、
フラグが立ちっぱなしになり**押し続けたのと同じ状態**になる。

### 3-3. iframe で例外を投げる API は全部 try/catch

`localStorage`（クロスサイト追跡防止）／`AudioContext` の生成／
`requestFullscreen`／`window.top` 参照。
**特に初期化中の例外は、ゲーム本体の生成ごと巻き込んで真っ暗にする。**

### 3-4. 「押しても何も起きないボタン」を画面に置かない

例：iPhone Safari は要素の全画面表示に非対応なので、全画面ボタンは
**何もしないのに操作領域を食うだけ**になる。
非対応環境では消す（`document.fullscreenEnabled` で判定）。

## 4. 端末だけで原因を割り出す（これが決め手になる）

画面の隅に極小で2行出す。

```
BUILD 2026-09-15 02:34 a1b2c3d
D3 M12 U3 X0 T3 C0 Tw down 137,612 R412x551
```

| 記号 | 意味 |
|---|---|
| `D` | pointerdown の**生の**受信数 |
| `M` | move の生の受信数 |
| `U` | up の生の受信数 |
| `X` | cancel の生の受信数 |
| `T` | touchstart の生の受信数 |
| `C` | DOM ボタンの click の受信数 |
| `Tw`等 | どの系統で届いたか（w=window / d=document / h=html / c=canvas） |
| `R` | キャンバスの実表示サイズ |

**読み方**

- BUILD の日付が古い → **キャッシュ**。修正内容の問題ではない
- 全部 0 のまま → イベントがゲームまで届いていない
- `C` だけ増える → click しか通らない環境（アプリ内ブラウザ等）
- `D` は増えるが `M` が増えない → ドラッグ情報が来ていない
- `X` が増える → ブラウザにジェスチャーを取り消されている
- `R` が 0 や異常値 → レイアウト／座標変換が壊れている

**★ カウンタは必ず「フィルタ前の生イベント数」にすること。**
自前の条件分岐の後で数えると、実際には届いているのに 0 と表示され、
切り分けの役に立たない（一度これで遠回りした）。●

**普段は出さない。** `?debug=1` のときと、
「操作しているのに入力が1件も届いていない」異常時だけ自動表示にする。

## 5. キャッシュ自動復旧

ビルド時に BUILD ID と `version.json` を出し、起動時に照合して読み直す。

```ts
// 起動時（ゲーム本体には影響させない）
const probe = new URL('version.json', document.baseURI);
probe.searchParams.set('_', String(Date.now()));
fetch(probe.toString(), { cache: 'no-store' })
  .then(r => r.ok ? r.json() : null)
  .then(d => {
    if (!d?.build || d.build === __BUILD_ID__) return;
    const here = new URL(location.href);
    if (here.searchParams.get('v') === d.build) return; // 無限リロード防止
    here.searchParams.set('v', d.build);
    location.replace(here.toString());
  })
  .catch(() => {});
```

簡易版として、資産の参照に `?v=20260915-01` のような文字列を付けるだけでも効く。

## 6. 性能

### 6-1. 配列

- **大きい配列のループの中で `splice` しない。**
  寿命切れを1件ずつ `splice` すると O(n²)。1パス・コンパクションにする：

```ts
let w = 0;
for (let i = 0; i < arr.length; i++) {
  const p = arr[i];
  update(p);
  if (alive(p)) { if (w !== i) arr[w] = p; w++; }
}
arr.length = w;
```

  ● 実測：パーティクル11,000個で `update` が 1フレーム 147ms。上の形にして **0.5ms**。
- **無制限に増えうるものには必ず上限を置く。** 上限は「普段は絶対に触れない高さ」に。
- **画面外に出たものは update の同じパスで捨てる。**

### 6-2. 音（見落としやすい）

- **`setInterval` で音楽を鳴らさない。**
  タイマーはメインスレッドが混むと遅れて起き、**その遅れがそのままテンポの乱れ**になる。
  → タイマーは「予約しに行くきっかけ」に徹し、
  **オーディオ時計（`ctx.currentTime`）基準で先読み予約**する。
  次の音の時刻は `nextNoteTime += beat` と**足し算で積む**（起きた時刻は使わない）。

```ts
const LOOKAHEAD = 0.18;
let nextNoteTime = ctx.currentTime + 0.06;
setInterval(() => {
  if (nextNoteTime < ctx.currentTime - 0.3) nextNoteTime = ctx.currentTime + 0.03; // 復帰時の貼り直し
  while (nextNoteTime < ctx.currentTime + LOOKAHEAD) {
    playNoteAt(nextNoteTime);      // ← 「今」ではなく「予約時刻」
    nextNoteTime += beat;
  }
}, 40);
```

  ● 実測（本来125ms間隔）：修正前は負荷時に **70〜171ms（±18.5ms）** まで暴れていた。
  修正後は負荷をかけても **125.0ms ±0.0ms**。
- **「音楽がもたつく」という報告は感想ではなく計測値として扱う。**
  BGM のテンポの乱れは、そのままメインスレッド負荷のメーターになる。
- 効果音の波形を毎回 JS ループで合成しない。種類ごとに数パターン作って使い回す。
- **長尺 mp3 を `decodeAudioData` しない。**
  8MB / 6分の曲は PCM で **約134MB** になり、セッション中ずっと保持される。
  スマホではメモリ強制終了の危険域。長尺は `<audio>` でストリーム再生する。

### 6-3. Canvas 描画

- `ctx.shadowBlur` はモバイルGPUで非常に重い。**使ったら次の描画前に `0` に戻す**
  （戻さないと後続の描画にも二重にかかる）。
- `shadowBlur` は **`ctx.scale()` の影響を受ける**。拡大した状態で設定すると
  ぼかし半径が倍率ぶん膨らむ。
- **小数の `translate` を避ける**（画面揺れ等）。以降の全矩形が
  アンチエイリアス経路に落ちる。整数に丸めた方が速く、ドット絵もボケない。
- `canvas.getContext('2d', { alpha: false })`。透明キャンバスは毎フレーム
  背景と合成が必要で、スマホでは不利。
- 中身が変化しない複雑な絵は**オフスクリーンに焼いて `drawImage` 1回**にする。
  毎フレーム作り直しているグラデーション等はキャッシュする。
- 描画状態の変更（`fillStyle` / `globalAlpha`）はまとめる。**データを先にソートしておく。**
- **画面外のものは描画ごと省く。**

### 6-4. 当たり判定

- 名前が `checkXxx` の関数に**副作用を持たせない**。
  「判定する前にエフェクトを出す」関数を、距離チェック無しで全オブジェクトに
  対して呼んでいると、**画面外の敵からもエフェクトが出続ける**。
  ● 実際に踏んだ：最大 768個/フレームの無駄なパーティクル。性能と見た目の同時バグ。
- 重い判定の前に**必ずブロードフェーズ**（外接矩形）を置く。

### 6-5. 計測の作法

- **体感報告は必ず計測に変換してから直す。**
  ● 実際、「描画が重い」と思い込んで調べたら犯人は `update` だった。
- **A/B は「1つずつ切って交互に測る」。** まとめて切ると何が効いたか分からない。
  周囲の負荷でブレるので、同一実行内で交互に測って相対差を見る。
- JS の CPU プロファイルは**GPU のラスタライズ・合成を見ていない**。
  「JS はアイドル 80%」でもフレームが落ちることはある。

## 7. 新規プロジェクトの1日目にやること

- [ ] ビルド時に BUILD ID を埋め込み、画面の隅に出す
- [ ] `version.json` を出して起動時に照合・自動リロード
- [ ] 入力の生イベントカウンタを実装（`?debug=1` で表示）
- [ ] 入力リスナーを多重登録＋重複排除、`capture: true`
- [ ] タッチは Touch Events 主系統、`touchmove` は `preventDefault`
- [ ] 解放経路を多重化＋ウォッチドッグ
- [ ] タイトルに透明 DOM `<button>`（既定で表示・その上では `preventDefault` しない）
- [ ] rAF 再登録を `finally` に
- [ ] `localStorage` / `AudioContext` / `requestFullscreen` を try/catch
- [ ] `getContext('2d', { alpha: false })`
- [ ] CSS: `touch-action: none` / `overscroll-behavior: none` / `user-select: none`
- [ ] パーティクル等に上限、配列は1パス・コンパクション
- [ ] 音はオーディオ時計で先読み予約
- [ ] **実機（できれば古い端末）で触る工程を、機能を作る前にスケジュールへ入れる**

## 8. 症状 → 原因の逆引き

| 症状 | まず疑うこと |
|---|---|
| 直したのに直らない（2回以上） | キャッシュ。BUILD ID を見る |
| 画面は出るがタップに無反応 | rAF が例外で停止／リスナーが届いていない |
| タイトルは効くがゲーム中だけ効かない | `move` が来ていない／ゾーン判定の座標がおかしい |
| タップは効くがホールドが効かない | `pointercancel` で即解放されている |
| 一度触ったら以後ずっと無反応 | 解放イベント取りこぼしで状態がラッチしている |
| BGM がもたつく | メインスレッド負荷。`setInterval` で鳴らしていないか |
| 画面外でエフェクトが出る | 判定関数の副作用＋ブロードフェーズ欠落 |
| 平均fpsは出ているのに引っかかる | GC（毎フレームの確保）か、瞬間的な重い処理 |
| スマホだけ重い | GPU 合成・オーバードロー。JSプロファイルには映らない |
| 縦長・横長の画面で絵が伸びる・潰れる | 置き場所いっぱいに引き伸ばしている。縦横比を保って余りは黒帯(§9-5) |
| 記録したプレイを再生すると結果がずれる | 記録は丸めて本番は小数のまま／bot が中身と同じ乱数を使っている(§9-6) |
| Phaser 4 で点線の弧がつながって崩れる | 1 本の path に arc を重ねている。弧ごとに path を分ける(§9-7) |
| SNS のリンクから開くとアプリ内ブラウザで、音・全画面・保存が効かない | 雛形は `core/inapp.ts` が上に「ブラウザで開く」を出す(LINE は自動で外部へ)。`?inapp=1` で見た目を確認 |
| スマホでキーボードを出すと絵が縮む | 大きさを visualViewport の高さに比例させている(§9-15) |
| コントローラ対応を自動テストで確かめたい | getGamepads を偽のパッドに差し替える(§9-16) |
| アプリ内ブラウザで横向きにならない | 向きが縦に固定されている。入れ物を CSS で回し、縮尺とタップ座標を自前で(§9-8) |
| Phaser の字が欠ける・フォントが違う | 1 文字ずつの Text / Web フォントの読み込み前に描いた(§9-9) |
| bot の成績が急に崩れた | バランスより先に中身のバグ(写しと状態の上書き順など)(§9-10) |
| Canvas の切り抜きが薄く残る | 切る形の fillStyle が半透明のまま。不透明にする(§9-12) |
| Facebook でリンクに絵が出ない | og:image:width/height が無い・古い結果を覚えている。シェアデバッガーで取り直す(§9-13) |
| 自動テストで曲の時計を差し替えたのに時間が止まる | 差し替えが曲の開始処理より前。後にする(§9-14) |
| 音が大きいと言われる | AI の音量は大きめになりがち。`audio.sfx` / `audio.bgm` を下げる(§9-11) |

## 9. 他の作品から回収した実機ノウハウ(2026-10-01 追記)

過去作の docs を洗って見つけたもの。出所の作品名を残す。

### 9-1. iPhone のサイレントスイッチで Web Audio だけ鳴らない(NeoSoukoban v1.20.5)

- 症状: iPhone だけ音が出ない。Android は鳴る。YouTube は iPhone でも鳴る。
- 原因: iOS では本体のサイレントスイッチで **Web Audio API の音がミュートされる**。
  一方 `<audio>` / `<video>` 要素の再生はスイッチの影響を受けないことが多い。
- 対策: 無音の短い WAV をループ再生する `<audio>` 要素を置き、**ユーザー操作のたびに `.play()`**
  (AudioContext の resume と同じタイミング。再生中なら何もしないので毎回呼んで無害)。
  `visibilitychange` でアプリ復帰時にも再開を試みる。
- **注意: Chromium では再現できず、実機 iPhone での効果は未確認**(元の記録にもそう書いてある)。
  → `src/core/audio.ts` への組み込み(0 層化)は、実機で確かめてから。

### 9-2. やり直し・undo の直後に、古い遅延処理が新しい状態を壊す(NeoSoukoban v1.15.17)

- 症状: 10 回中 4 回だけ、演出が一瞬で終わる。再現が不安定に見える。
- 原因: `setTimeout` の演出が、リトライ後も生き残って発火し、**新しい試行の状態を消していた**。
  同じ面をやり直すと配列の添字が同じになるので、古いタイマーが新しい対象を触る。
- 対策: **世代カウンタ**(`playGen`)を持ち、面の開始・やり直し・undo のたびに +1。
  遅延処理は発火時に「自分の世代 !== 今の世代」なら何もせず抜ける。
- Phaser のシーンの `time.delayedCall` はシーン再起動で消えるが、**素の `setTimeout` は消えない**。

### 9-3. スマホで横画面を強制する(ImoteControllDandy)

1. スタート時に全画面 + `screen.orientation.lock('landscape')`(Android Chrome。**ユーザー操作の中でしか許可されない**)
2. それでも縦のまま(iPhone Safari・自動回転オフ)なら、**アプリ全体を CSS で 90° 回す**
   (`width:100dvh; height:100dvw; rotate(90deg)`)。このとき**タッチ座標も 90° ずれる**ので変換関数を通し、
   画面サイズは `window.innerWidth` ではなく回した後の大きさを使う
3. ホーム画面に追加(PWA)した時は `manifest.webmanifest` の `orientation: landscape` が効く
- 「横にしてね」の案内は不要になる(縦でも横画面で遊べるため)

### 9-5. 縦長・横長モニタで画面が引き伸ばされる(作品セッションから回収 2026-10-03)

- 症状: 縦長モニタで絵が縦に伸びた。モニタやブラウザの問題に見えるが、**こちらの作りの問題**。
- 原因: canvas を置き場所(ウィンドウ)いっぱいに縦横別々に引き伸ばしていた。
- 修正: **縦横比を保ったまま入る最大の大きさ**に拡大し、余った分は黒い帯(レターボックス)にする。
  大きいモニタではそのぶん大きく表示する。PC もスマホも同じ処理。
  (Phaser なら `scale.mode = Phaser.Scale.FIT` + `autoCenter: CENTER_BOTH`。素の canvas なら
  `scale = Math.min(W/幅, H/高さ)` で CSS サイズを決め、タッチ座標も同じ scale で戻す)
- 確かめ方: **縦長・横長・スマホ縦・スマホ横の 4 つの画面サイズ**で、比率が崩れないことを見る
  (Playwright の viewport を 4 通りにしてスクショ)。

### 9-4. 自動テストのヘッドレスブラウザで、ゲームループが止まる(panzer-tokoron)

- **スクショを撮った後に `requestAnimationFrame` が凍結**してループが止まることがある(ヘッドレス Edge で 3 回再現)。
  長時間の自動プレイでは途中のスクショを避けるか、間隔を短くする。
- バックグラウンド扱いのタブでは rAF が止まる。
  `--disable-backgrounding-occluded-windows --disable-features=CalculateNativeWinOcclusion` を付ける。
- 雛形の `tools/check.mjs` は Chromium で通っているが、**Edge や長時間テストに切り替える時は注意**。

### 9-6. 記録したプレイを再生すると結果がずれる(obake-chochin 2026-10-06)

- 症状: 人間のタップを記録して再生すると、スコアや展開がずれることがある。
- 原因: 記録は座標を整数に丸めるのに、本番は小数の座標のまま動かしていた。また bot が中身と同じ乱数を引いていて、bot の有無で乱数の並びが変わった。
- 修正: 中身の入口(tap などの入力関数)で座標を丸める。bot には中身とは別の乱数を持たせる。
- 確かめ方: bot の入力を記録 → 文字列 → 再生して、スコアとフレーム数が一致することを見る(§10 の再現の仕組み)。
- 未確認: 実機での長時間プレイ。
- おまけ: bot の決定から入力までを lag 秒遅らせて成績を見ると「反射神経ゲームか」を数字で測れる。0.02 秒で急に崩れるような段差が出たら、ゲームより bot の穴を疑う。

### 9-7. Phaser 4 の Graphics で点線の弧がつながって崩れる(obake-chochin 2026-10-06)

- 症状: `beginPath → arc → strokePath` を繰り返して点線の円を描くと、弧どうしが直線でつながって崩れた。
- 原因: 前の弧の終点から次の弧の始点へ線が引かれている(path が切れていない)。
- 修正: `lineBetween` で短い線分に区切って描く。
- 確かめ方: スクショで点線の円が正しく出ることを見た。
- 未確認: Phaser 3 で同じことが起きるか。

### 9-8. アプリ内ブラウザでは横向きにならない(obake-chochin 2026-10-07)

- 症状: スマホを横にしても縦画面のまま。
- 原因: Claude・X・LINE などのアプリ内ブラウザは向きを縦に固定することがあり、ページからは変えられない(§9-3 の強制も効かない)。
- 修正: 端末が縦長の時は、ゲームの入れ物を CSS で 90 度回して全面に出す。縮尺は Phaser の FIT を使わず自前で計算する(FIT は親の見た目の大きさを見るので、回すと縦長と誤解する)。タップ座標も回転に合わせて変換する。
- 確かめ方: Playwright で縦持ち・横持ち・PC の 3 通り、ゲーム座標の同じ点を押して同じ座標が届くこと。
- 未確認: 実機の iOS / Android。
- 関連(10/14 emmichy): アプリ内ブラウザでは初回に「外部ブラウザで開く・URL をコピー・このまま遊ぶ」を出し、設定から再表示できるようにした。案内を出している間はゲームの時計を止める。雛形は `core/inapp.ts`。

### 9-9. Phaser の文字が欠ける・Web フォントが間に合わない(obake-chochin 2026-10-08)

- 症状: 1 文字ずつ別の Text にして影・太いふちを付けると、字が欠けることがあった。
- 原因: 文字ごとの Text とふちの描画の組み合わせ。Web フォント(Google Fonts)は文字ごとに分けて配られるので、使う字が届く前に描くと別の字形になる。
- 修正: 1 つの Text にする。影は少しずらした同じ文字を後ろに置き、色は横向きのグラデーションで付ける。使う文字を全部まとめて `document.fonts.load` してから画面を作る。
- 確かめ方: スクショで字が欠けないこと。
- 未確認: Phaser 3。

### 9-10. bot の成績が急に崩れたら、まず中身の不具合を疑う(obake-chochin 2026-10-08)

- 症状: 「敵が渋滞する」「bot のクリア率が急に 0%」。絵では気づきにくい。
- 原因: 次の位置を写し(clone)で計算し、成功したら `Object.assign(g, clone)` で戻す作りで、assign の前に `g.stopped = false` と書いていた。写しの古い `stopped = true` で上書きされ、止まった印が永遠に残った。
- 修正: 状態を直すのは assign の後(または写しの側を直す)。
- 確かめ方: bot のクリア率が元に戻った。
- 教訓: bot の成績の崖(§9-6 の lag の段差と同じ)は、ゲームバランスより先に中身のバグを疑う。

### 9-11. 絵の動きを BGM の拍に合わせる(obake-chochin 2026-10-08)

- やり方: 曲の BPM と最初の拍を、音の立ち上がりの自己相関で測る(ffmpeg で生の波形に → numpy)。再生開始時刻と `AudioContext.currentTime` から曲の位置 → 拍の位置を出して、跳ねる周期に使う。ループで戻っても曲の位置から計算するのでずれない。
- 音量: AI が決める音量は大きめになりがち(聴かずに「ちゃんと聞こえる」値を選ぶ)。効果音と BGM は別のつまみ `audio.sfx` / `audio.bgm`(既定 0.45、`core/audio` の `sfxVolume()` / `bgmVolume()`)。
- 未確認: 人の耳でのずれの許容幅。

### 9-12. Canvas の切り抜きが薄く残る(obake-chochin 2026-10-08)

- 症状: `globalCompositeOperation = 'destination-out'` で三日月を切り抜いたら、影の部分がうっすら明るく残った。
- 原因: 直前に塗った色(透明度 35%)の fillStyle が残っていて、切り抜きも 35% しか効かなかった。
- 修正: 切る前に `fillStyle = '#000'`(不透明)にする。
- 確かめ方: 画面で三日月・ふくらむ月・満月が描き分けられた。
- 未確認: なし。

### 9-13. Facebook でリンクに絵が出ない(obake-chochin 2026-10-08、ほかの作品でも)

- 症状: og:image は絶対 URL、`public/og.png`(1200×630)もあるのに、Facebook のリンクに絵が出ない。
- 原因(見込み): `og:image:width` / `height` が無いと、初回に絵を後回しにして絵なしのまま覚えることがある。Facebook は一度取った結果を長く覚える。og.png が作り始めの古い画面のままだった。
- 修正: 雛形の index.html に width / height / type / secure_url / alt と twitter:image を最初から入れた。見た目を変えたら og.png を撮り直す。
- 確かめ方: 人間が https://developers.facebook.com/tools/debug/ に URL を入れて「もう一度取得」。
- 未確認: Facebook での表示(クラウドからは届かない)。

### 9-14. 自動テストで曲の時計を差し替えたのに時間が止まる(作品セッション 2026-10-10)

- 症状: 自動テストで、音に合わせて進むゲームの時計(AudioContext.currentTime など)を偽物に差し替えたのに、時間が進まない。
- 原因: 差し替えを曲の開始処理より前にしたため、開始処理が本物の時計で上書きした。
- 修正: 差し替えは曲の開始処理の**後**にする。
- 確かめ方: 自動テストで拍が進み、判定が動くこと。
- 未確認: 他のエンジンの音の時計。

### 9-15. スマホで文字入力を始めると絵が縮む(emmichy 2026-10-13)

- 症状: 入力欄をタップしてキーボードが出ると、キャラの絵や画面全体が小さくなる。
- 原因: 画面の大きさを `visualViewport` の高さに比例させていた(キーボードで高さが半分になる)。縦向き専用の CSS も重なった。
- 修正: 大きさは幅を基準に決めて固定する。`visualViewport` の resize・scroll と offsetTop に追従して位置だけ合わせ、キーボードが出ている間は見せたい物(顔など)が見える範囲に来るよう切り抜く。スマホでは開始時に入力欄へ自動でフォーカスしない。
- 確かめ方: Playwright でビューポートの高さを半分に変え、絵の大きさが変わらないこと。
- 追記(10/14): 絵はキーボードに合わせて上下に動かさず、最初から顔(見せたい物)が中央に来る位置で固定する方が揺れない。
- 未確認: 実機の OS キーボード(iOS / Android)。

### 9-16. コントローラ対応を自動テストで押したい(metopon 2026-10-13)

- 症状: Playwright にはゲームパッドを押す手段が無く、コントローラ対応を確かめられない。
- 原因: ブラウザのゲームパッドは本物の機器が要る。
- 修正: テストの中で `navigator.getGamepads` を偽のパッド(`buttons[i].pressed`・`axes` を持つ物)を返す関数に差し替え、フレームごとに値を変える。Phaser は `input: { gamepad: true }` で拾う。
- 確かめ方: 偽のパッドで A を押し、`core/input.ts` の action が 1 フレームだけ立つこと。
- 未確認: 実機ごとのボタン番号の違い(標準配置以外)。

## 10. AI に作らせるゲームは「再現できる」形にする(erukiti 2026-10-01 / NeoSoukoban の実例)

出典: [erukiti の投稿](https://x.com/erukiti/status/2105603325806936461)。過去作 NeoSoukoban が既にこの形(engine.js / levels.js を描画から分け、E2E とソルバーで全面を検証)。

1. **決定論的にする**: 乱数は seed 付き。seed + 操作の列でプレイを完全に再現できる。その記録を**文字列にしてコピーできる**ようにする(バグ報告がそのまま再現手順になる)
2. **ゲームの中身(ロジック)と描画を分ける**
3. **AI には中身だけを遊ぶ bot を作らせる**。描画を通さないので速く、スクショも不要で**トークンが安い**
4. bot のプレイや記録したプレイを**リプレイ**できるようにする(人間が目で確かめる時だけ描画を通す)

- 乱数のあるゲーム・描画が重いゲームほど効くが、**どのジャンルでも効く**。最初に入れないと後から分けるのは大変。
- 注意: プレイが長いと記録が大きくなる。その時は途中の状態を保存して区切る。
